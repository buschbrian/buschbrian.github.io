Utah Reservoir Dashboard

A live map and data workspace for current reservoir storage across Utah-connected drainage areas. The project combines verified capacity, 12 months of history, and two federal data sources.

Reservoirs69 across Utah-connected drainage areas
Data sourcesReclamation RISE and NRCS AWDB
RefreshDaily via GitHub Actions
ApplicationArcGIS Maps SDK 5.1, Calcite 5, and TypeScript

Reservoir data is difficult to compare in a table. This dashboard puts 69 reservoirs on one map and in one data workspace. The scope follows drainage areas that connect to Utah, and every published drainage area now has tracked storage. It includes relevant sites outside the state and keeps the source record for each site. Lake Powell stays in the source data but is excluded from the default views by its stable source identifier, so one very large reservoir does not dominate every total.

Capacity and history

Percent full now uses physical capacity when a verified figure is available. Reclamation sites use the National Inventory of Dams. AWDB sites use provider metadata. The highest observed storage since 2015 remains a labeled fallback when capacity is not available. The dashboard also shows normal storage for the week, history rank, change over time, and 12 months of monthly history.

Reading depletion as a shape

Each reservoir renders as two circles: a gray outline ring sized by that reservoir's full level, and a colored filled circle on top sized by current storage. The gap between ring and fill is a direct visual read of depletion. Both radii come from the same square-root-scaled size domain. This scale fits the largest reservoirs at millions of acre-feet and the smallest at a few thousand into one legible spread — and the fill is sized as a share of its own ring, so the ring-to-fill ratio always means percent depletion regardless of the reservoir's absolute size. Fill color uses five equal 20-point bands on an accessible red-to-blue scale. Low storage is red and high storage is blue, and the same class table drives the renderer, the legend, the filters, and the charts.

A pipeline that refreshes itself

A Python pipeline reads storage observations from the RISE and AWDB APIs. It validates each source and writes one reservoirs.json file. A GitHub Actions workflow runs it every morning at 6 a.m. Mountain, so the dashboard stays current with no server to maintain. RISE data is provisional per Reclamation's own disclaimer, and the app surfaces that caveat — in the title panel and in every popup — rather than presenting the most recent days as settled.

From comparison to product

The project began as an ArcGIS and MapLibre rendering comparison. Those pages remain available as stable comparison views. The current product is a responsive ArcGIS 5.1 application built with TypeScript, Vite, and Calcite components.

The map supports keyboard selection, storage and freshness filters, a month slider, and shareable URL state. A sortable reservoir table opens under the map and exports exactly the rows and order on screen as a CSV file. A separate ArcGIS Charts workspace links summary values, charts, and an exact-value table. Six-digit drainage areas give the reservoir points geographic context and define the accepted scope.

The numbers are documented, not just displayed. A methods page explains where each value comes from and how it is worked out. A public data API page publishes stable JSON paths, complete field definitions, and code examples, so the same validated data is usable outside the dashboard.

The repository now has strict TypeScript checks, unit tests, Python pipeline tests, a bundle budget, and Playwright browser tests. The browser tests cover desktop and phone layouts, data failures, map controls, and the reservoir count from the current data file.

View the live dashboard, the data workspace, the methods page, the public data API, the MapLibre GL version, or the source on GitHub. Data: Bureau of Reclamation RISE and NRCS AWDB.
