# Language style

## Decision

Use an ASD-STE100-aligned house style for all new and changed text. Use the official name, **ASD-STE100 Simplified Technical English**.

This repository does not claim full ASD-STE100 conformance. Full conformance requires the official Issue 9 writing rules and controlled dictionary. The portfolio also contains marketing copy, which is outside the standard's original purpose.

## Required rules

1. Use American English spelling.
2. Use active voice when the actor is important.
3. Put one main topic in each sentence.
4. Keep sentences short. Use 20 words or fewer when the meaning permits it.
5. Use one term for one item or concept.
6. Use the same technical term throughout a page.
7. Use short, common words when they keep the correct meaning.
8. Explain a GIS term when a general reader might not know it.
9. Use lists for sequences and sets of three or more items.
10. Use direct instructions in contribution guides and templates.
11. Do not use slang, idioms, or decorative jargon.
12. Do not join independent ideas with an em dash.

## Technical terms

Technical nouns can include product names, standards, job titles, place names, and GIS terms. Examples include ArcGIS Online, MapLibre GL JS, GISP, GNSS, and Wildland-Urban Interface.

Use a technical term only when it gives necessary information. Define it on first use if a general reader might not know it.

## Examples

Use this:

> The dashboard gets reservoir data from the RISE API. GitHub Actions refreshes the data each day.

Do not use this:

> A live dashboard tracking drought across 28 Utah reservoirs, with data refreshed daily via GitHub Actions.

Use this:

> The script gives a different color to each adjacent polygon. This method makes district boundaries easier to read.

Do not use this:

> The script utilizes a graph-coloring approach to automatically assign unique colors to neighboring polygons.

## GitHub text

- Start a commit subject with an action verb.
- Keep a commit subject to one change.
- State the problem and result in a pull request description.
- Use short checklist items.
- Put commands, file names, and identifiers in code formatting.
- Use the official project terms from the site.

## Review checklist

- Does each sentence have one main topic?
- Can you replace a long word with a short word without changing the meaning?
- Does each technical term have one meaning?
- Does the text explain necessary GIS terms?
- Does the text use American English?
- Did you remove unnecessary em dashes and parenthetical text?
